# Приложение. Структура базы данных

Ниже приведена предлагаемая структура базы данных для проекта SmartTeach. Она опирается на уже зафиксированные сущности сервиса: пользователей, группы, уроки, задания, расписание, чаты и административные сценарии. В качестве СУБД используется `PostgreSQL`, а доступ к данным на уровне приложения предполагается через `Prisma`.

Документ описывает концептуальную структуру БД. Конкретные имена таблиц, индексов и enum-типов могут быть уточнены при проектировании `Prisma Schema`, но состав сущностей и их поля должны оставаться близкими к описанной ниже модели.

## Общие принципы

- Для основных сущностей используется первичный ключ `id` типа `UUID`.
- Все пользовательские и учебные сущности должны содержать поля аудита `createdAt` и `updatedAt`.
- Связи многие-ко-многим оформляются через отдельные таблицы-связки.
- Для ролей, статусов и типов событий должны использоваться `enum`-значения на уровне БД и приложения.
- Файлы хранятся во внешнем объектном хранилище `MinIO`, а в БД сохраняются только метаданные и ключи доступа.

## 1. Пользователи

### Таблица `users`

Основная таблица пользователей сервиса. Содержит данные профиля, роль на уровне всей платформы и информацию, необходимую для локальной авторизации.

| Поле | Тип | Назначение |
| --- | --- | --- |
| `id` | `UUID` | Первичный ключ пользователя. |
| `email` | `VARCHAR` | Уникальный адрес электронной почты для входа и связи с пользователем. |
| `passwordHash` | `VARCHAR` | Хэш пароля для локальной авторизации. Может быть `NULL`, если пользователь входит только через OAuth. |
| `displayName` | `VARCHAR` | Отображаемое имя пользователя в интерфейсе сервиса. |
| `bio` | `TEXT` | Краткое описание пользователя или информация о себе. |
| `avatarFileId` | `UUID` | Ссылка на файл аватара в таблице `files`. Может быть `NULL`. |
| `serviceRole` | `ENUM` | Глобальная роль пользователя в системе: `USER`, `MODERATOR`, `ADMIN`. |
| `emailVerifiedAt` | `TIMESTAMPTZ` | Дата подтверждения электронной почты. Может быть `NULL`. |
| `lastLoginAt` | `TIMESTAMPTZ` | Время последнего успешного входа. Может быть `NULL`. |
| `createdAt` | `TIMESTAMPTZ` | Дата и время создания записи. |
| `updatedAt` | `TIMESTAMPTZ` | Дата и время последнего обновления записи. |

### Таблица `oauth_accounts`

Связка пользователя с внешними провайдерами авторизации. Нужна для поддержки входа через OAuth без дублирования учетных записей.

| Поле | Тип | Назначение |
| --- | --- | --- |
| `id` | `UUID` | Первичный ключ записи внешней авторизации. |
| `userId` | `UUID` | Ссылка на пользователя из таблицы `users`. |
| `provider` | `VARCHAR` | Код провайдера авторизации, например `google` или `github`. |
| `providerUserId` | `VARCHAR` | Идентификатор пользователя у внешнего провайдера. |
| `accessToken` | `TEXT` | Токен доступа провайдера. При хранении должен быть зашифрован. Может быть `NULL`. |
| `refreshToken` | `TEXT` | Токен обновления провайдера. При хранении должен быть зашифрован. Может быть `NULL`. |
| `expiresAt` | `TIMESTAMPTZ` | Срок действия внешнего токена. Может быть `NULL`. |
| `createdAt` | `TIMESTAMPTZ` | Дата и время создания записи. |
| `updatedAt` | `TIMESTAMPTZ` | Дата и время последнего обновления записи. |

### Таблица `sessions`

Хранит пользовательские сессии и refresh-токены. Нужна для безопасного продления авторизации, выхода со всех устройств и отзыва токенов.

| Поле | Тип | Назначение |
| --- | --- | --- |
| `id` | `UUID` | Первичный ключ сессии. |
| `userId` | `UUID` | Ссылка на пользователя из таблицы `users`. |
| `refreshTokenHash` | `VARCHAR` | Хэш refresh-токена, а не сам токен в открытом виде. |
| `userAgent` | `TEXT` | Информация об устройстве и браузере. Может быть `NULL`. |
| `ipAddress` | `INET` | IP-адрес клиента. Может быть `NULL`. |
| `expiresAt` | `TIMESTAMPTZ` | Срок действия сессии. |
| `revokedAt` | `TIMESTAMPTZ` | Время отзыва сессии. Может быть `NULL`. |
| `createdAt` | `TIMESTAMPTZ` | Дата и время создания записи. |
| `updatedAt` | `TIMESTAMPTZ` | Дата и время последнего обновления записи. |

## 2. Файлы

### Таблица `files`

Содержит метаданные файлов, загруженных в систему. Сами бинарные данные размещаются в `MinIO`.

| Поле | Тип | Назначение |
| --- | --- | --- |
| `id` | `UUID` | Первичный ключ файла. |
| `storageKey` | `VARCHAR` | Уникальный ключ объекта в хранилище `MinIO`. |
| `fileName` | `VARCHAR` | Исходное имя файла. |
| `mimeType` | `VARCHAR` | MIME-тип файла. |
| `size` | `BIGINT` | Размер файла в байтах. |
| `bucket` | `VARCHAR` | Имя bucket'а в объектном хранилище. |
| `uploadedById` | `UUID` | Пользователь, загрузивший файл. Может быть `NULL` для служебных загрузок. |
| `isPublic` | `BOOLEAN` | Признак публичной доступности файла. |
| `createdAt` | `TIMESTAMPTZ` | Дата и время загрузки файла. |

## 3. Группы и участники

### Таблица `groups`

Центральная сущность проекта. Любой учебный сценарий строится вокруг группы, а класс и курс рассматриваются как разновидности группы с разной конфигурацией.

| Поле | Тип | Назначение |
| --- | --- | --- |
| `id` | `UUID` | Первичный ключ группы. |
| `name` | `VARCHAR` | Название группы. |
| `description` | `TEXT` | Описание группы, цели или правила участия. Может быть `NULL`. |
| `kind` | `ENUM` | Тип группы, например `BASIC`, `CLASS`, `COURSE`. |
| `visibility` | `ENUM` | Видимость группы: публичная или приватная. |
| `moderationStatus` | `ENUM` | Статус модерации группы на уровне сервиса. |
| `ownerId` | `UUID` | Пользователь-владелец группы. |
| `inviteCode` | `VARCHAR` | Код приглашения для вступления. Может быть `NULL`. |
| `chatEnabled` | `BOOLEAN` | Включен ли модуль чатов в группе. |
| `lessonsEnabled` | `BOOLEAN` | Включен ли модуль уроков. |
| `assignmentsEnabled` | `BOOLEAN` | Включен ли модуль домашних заданий. |
| `scheduleEnabled` | `BOOLEAN` | Включен ли модуль расписания. |
| `createdAt` | `TIMESTAMPTZ` | Дата и время создания группы. |
| `updatedAt` | `TIMESTAMPTZ` | Дата и время последнего обновления группы. |

### Таблица `group_members`

Связывает пользователей и группы. Через эту таблицу определяется состав участников и их роли внутри каждой группы.

| Поле | Тип | Назначение |
| --- | --- | --- |
| `groupId` | `UUID` | Ссылка на группу из таблицы `groups`. |
| `userId` | `UUID` | Ссылка на пользователя из таблицы `users`. |
| `role` | `ENUM` | Роль участника в группе: `OWNER`, `ADMIN`, `USER`. |
| `joinedAt` | `TIMESTAMPTZ` | Дата и время вступления в группу. |

Для таблицы `group_members` рекомендуется использовать составной первичный ключ `groupId + userId`.

### Таблица `group_moderation_logs`

История действий модерации по группам. Позволяет сохранять причину смены статуса и фиксировать, кто принял решение.

| Поле | Тип | Назначение |
| --- | --- | --- |
| `id` | `UUID` | Первичный ключ записи модерации. |
| `groupId` | `UUID` | Группа, по которой было принято решение. |
| `moderatorId` | `UUID` | Пользователь с административной или модераторской ролью, выполнивший действие. |
| `previousStatus` | `ENUM` | Предыдущее состояние модерации группы. |
| `newStatus` | `ENUM` | Новое состояние модерации группы. |
| `reason` | `TEXT` | Причина изменения статуса. Может быть `NULL`. |
| `createdAt` | `TIMESTAMPTZ` | Время фиксации действия. |

## 4. Учебные сущности

### Таблица `lessons`

Хранит уроки, создаваемые внутри группы или курса. Урок может быть опубликован сразу или подготовлен как черновик.

| Поле | Тип | Назначение |
| --- | --- | --- |
| `id` | `UUID` | Первичный ключ урока. |
| `groupId` | `UUID` | Группа, внутри которой создан урок. |
| `title` | `VARCHAR` | Название урока. |
| `description` | `TEXT` | Описание урока. Может быть `NULL`. |
| `order` | `INTEGER` | Порядковый номер урока внутри группы. |
| `startsAt` | `TIMESTAMPTZ` | Плановое время начала урока. Может быть `NULL`. |
| `endsAt` | `TIMESTAMPTZ` | Плановое время окончания урока. Может быть `NULL`. |
| `published` | `BOOLEAN` | Признак публикации урока для участников группы. |
| `createdAt` | `TIMESTAMPTZ` | Дата и время создания урока. |
| `updatedAt` | `TIMESTAMPTZ` | Дата и время последнего обновления урока. |

### Таблица `assignments`

Хранит домашние задания и другие задания, выдаваемые внутри группы. Задание может быть связано с конкретным уроком, но это не является обязательным требованием.

| Поле | Тип | Назначение |
| --- | --- | --- |
| `id` | `UUID` | Первичный ключ задания. |
| `groupId` | `UUID` | Группа, в которой создано задание. |
| `lessonId` | `UUID` | Ссылка на урок, если задание привязано к уроку. Может быть `NULL`. |
| `title` | `VARCHAR` | Название задания. |
| `description` | `TEXT` | Полное описание задания. Может быть `NULL`. |
| `dueAt` | `TIMESTAMPTZ` | Крайний срок сдачи. Может быть `NULL`. |
| `maxScore` | `INTEGER` | Максимальный балл за выполнение. Может быть `NULL`. |
| `published` | `BOOLEAN` | Признак публикации задания. |
| `createdAt` | `TIMESTAMPTZ` | Дата и время создания задания. |
| `updatedAt` | `TIMESTAMPTZ` | Дата и время последнего обновления задания. |

### Таблица `submissions`

Хранит сдачи заданий от пользователей. Сущность описывает текущее состояние отправленной работы, результат проверки и обратную связь.

| Поле | Тип | Назначение |
| --- | --- | --- |
| `id` | `UUID` | Первичный ключ сдачи. |
| `assignmentId` | `UUID` | Ссылка на задание из таблицы `assignments`. |
| `authorId` | `UUID` | Пользователь, отправивший решение. |
| `text` | `TEXT` | Текстовое содержимое ответа. Может быть `NULL`. |
| `status` | `ENUM` | Статус сдачи, например черновик, отправлено, проверено. |
| `score` | `INTEGER` | Выставленный балл. Может быть `NULL`. |
| `feedback` | `TEXT` | Комментарий преподавателя по проверке. Может быть `NULL`. |
| `submittedAt` | `TIMESTAMPTZ` | Момент фактической отправки работы. Может быть `NULL`. |
| `createdAt` | `TIMESTAMPTZ` | Дата и время создания записи. |
| `updatedAt` | `TIMESTAMPTZ` | Дата и время последнего обновления записи. |

### Таблица `submission_files`

Таблица-связка между сдачами и прикрепленными файлами. Нужна для хранения вложений к ответам пользователей.

| Поле | Тип | Назначение |
| --- | --- | --- |
| `submissionId` | `UUID` | Ссылка на сдачу из таблицы `submissions`. |
| `fileId` | `UUID` | Ссылка на файл из таблицы `files`. |
| `order` | `INTEGER` | Позиция файла в списке вложений. |

Для таблицы `submission_files` рекомендуется использовать составной первичный ключ `submissionId + fileId`.

### Таблица `schedule_events`

Описывает элементы расписания: занятия, дедлайны, встречи и другие временные события внутри группы.

| Поле | Тип | Назначение |
| --- | --- | --- |
| `id` | `UUID` | Первичный ключ события расписания. |
| `groupId` | `UUID` | Группа, к которой относится событие. |
| `title` | `VARCHAR` | Название события. |
| `description` | `TEXT` | Расширенное описание события. Может быть `NULL`. |
| `type` | `ENUM` | Тип события расписания. |
| `startsAt` | `TIMESTAMPTZ` | Дата и время начала. |
| `endsAt` | `TIMESTAMPTZ` | Дата и время окончания. |
| `lessonId` | `UUID` | Ссылка на урок, если событие связано с уроком. Может быть `NULL`. |
| `assignmentId` | `UUID` | Ссылка на задание, если событие связано с дедлайном. Может быть `NULL`. |
| `location` | `VARCHAR` | Текстовое указание места или формата проведения. Может быть `NULL`. |
| `createdAt` | `TIMESTAMPTZ` | Дата и время создания события. |
| `updatedAt` | `TIMESTAMPTZ` | Дата и время последнего обновления события. |

## 5. Коммуникация

### Таблица `chats`

Хранит чаты внутри групп. Для одной группы может существовать несколько чатов с разным назначением, например общий чат или канал объявлений.

| Поле | Тип | Назначение |
| --- | --- | --- |
| `id` | `UUID` | Первичный ключ чата. |
| `groupId` | `UUID` | Группа, к которой относится чат. |
| `title` | `VARCHAR` | Название чата. |
| `description` | `TEXT` | Описание назначения чата. Может быть `NULL`. |
| `type` | `ENUM` | Тип чата. |
| `isReadOnly` | `BOOLEAN` | Признак режима только для чтения. |
| `createdAt` | `TIMESTAMPTZ` | Дата и время создания чата. |
| `updatedAt` | `TIMESTAMPTZ` | Дата и время последнего обновления чата. |

### Таблица `messages`

Хранит сообщения внутри чатов. Сообщение может содержать текст и вложения.

| Поле | Тип | Назначение |
| --- | --- | --- |
| `id` | `UUID` | Первичный ключ сообщения. |
| `chatId` | `UUID` | Ссылка на чат из таблицы `chats`. |
| `authorId` | `UUID` | Пользователь, отправивший сообщение. |
| `text` | `TEXT` | Текст сообщения. Может быть `NULL`, если сообщение состоит только из вложений. |
| `createdAt` | `TIMESTAMPTZ` | Дата и время отправки сообщения. |
| `editedAt` | `TIMESTAMPTZ` | Дата и время последнего редактирования сообщения. Может быть `NULL`. |

### Таблица `message_files`

Таблица-связка между сообщениями и файлами. Позволяет прикреплять к одному сообщению несколько файлов.

| Поле | Тип | Назначение |
| --- | --- | --- |
| `messageId` | `UUID` | Ссылка на сообщение из таблицы `messages`. |
| `fileId` | `UUID` | Ссылка на файл из таблицы `files`. |
| `order` | `INTEGER` | Порядок отображения вложения в сообщении. |

Для таблицы `message_files` рекомендуется использовать составной первичный ключ `messageId + fileId`.

## 6. Служебные сущности

### Таблица `notifications`

Служебная сущность для уведомлений пользователя. Она нужна для отображения событий системы, связанных со вступлением в группы, дедлайнами, проверкой заданий и административными действиями.

| Поле | Тип | Назначение |
| --- | --- | --- |
| `id` | `UUID` | Первичный ключ уведомления. |
| `userId` | `UUID` | Пользователь, которому адресовано уведомление. |
| `type` | `ENUM` | Тип уведомления. |
| `title` | `VARCHAR` | Короткий заголовок уведомления. |
| `body` | `TEXT` | Полный текст уведомления. |
| `isRead` | `BOOLEAN` | Признак прочтения уведомления. |
| `relatedGroupId` | `UUID` | Ссылка на группу, если уведомление связано с ней. Может быть `NULL`. |
| `relatedLessonId` | `UUID` | Ссылка на урок, если уведомление связано с уроком. Может быть `NULL`. |
| `relatedAssignmentId` | `UUID` | Ссылка на задание, если уведомление связано с заданием. Может быть `NULL`. |
| `createdAt` | `TIMESTAMPTZ` | Дата и время создания уведомления. |
| `readAt` | `TIMESTAMPTZ` | Момент прочтения уведомления. Может быть `NULL`. |

## 7. Основные связи между сущностями

- Один пользователь может владеть несколькими группами через связь `users -> groups.ownerId`.
- Один пользователь может состоять во многих группах через таблицу `group_members`.
- Одна группа может содержать много уроков, заданий, событий расписания и чатов.
- Одно задание может быть связано с одним уроком, но урок может включать несколько заданий.
- Одно задание может иметь много сдач от разных пользователей.
- Одна сдача может иметь несколько вложенных файлов через таблицу `submission_files`.
- Один чат может содержать много сообщений.
- Одно сообщение может иметь несколько вложенных файлов через таблицу `message_files`.
- Один пользователь может иметь несколько OAuth-аккаунтов и несколько активных сессий.

## 8. Вывод

Предложенная структура БД покрывает основной функционал проекта: регистрацию и авторизацию пользователей, управление группами, учебный процесс, расписание, чаты и служебные сценарии платформы. Такая модель остается достаточно простой для первой версии системы, но при этом позволяет без смены архитектурного подхода развивать сервис дальше: добавлять новые роли, типы событий, интеграции и дополнительные механизмы модерации.
