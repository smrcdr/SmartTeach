# 2. Функциональный охват и ограничения

Этот документ фиксирует не целевые требования, а то, что уже реализовано в репозитории.

## Реализованный функционал

### 1. Аккаунт и авторизация

- регистрация пользователя
- вход по email и паролю
- выход
- получение текущего пользователя через `GET /auth/me`
- продление сессии через `POST /auth/refresh`
- редактирование собственного профиля
- просмотр профиля другого пользователя

### 2. Файлы

- загрузка файла через backend
- получение метаданных и ссылки на файл
- мягкое удаление файла
- использование файлов для:
  - аватаров пользователей
  - аватаров и изображений групп
  - изображений полезных ссылок
  - вложений уроков
  - вложений заданий
  - вложений в сдачах
  - вложений в сообщениях

### 3. Группы и доступ

- каталог групп с фильтрами
- просмотр группы по `id`
- просмотр группы по короткому коду
- создание, редактирование и удаление группы
- вступление в открытую группу
- выход из группы
- ручное добавление участников администраторами
- изменение роли участника внутри группы
- удаление участника из группы
- заявки на вступление для групп с режимом `BY_REQUEST`
- просмотр и обработка заявок администраторами группы

### 4. Настройки группы

Для группы можно включать и выключать модули:

- `chatEnabled`
- `lessonsEnabled`
- `assignmentsEnabled`
- `scheduleEnabled`
- `scheduleWeeklyEnabled`
- `scheduleSpecialEnabled`
- `usefulLinksEnabled`

### 5. Полезные ссылки группы

- просмотр списка полезных ссылок группы
- добавление новых ссылок администраторами группы
- поддержка изображения у ссылки

### 6. Материалы и уроки

- древовидные материалы: секции и подсекции
- создание, редактирование и удаление секций
- создание, редактирование и удаление подсекций
- просмотр подсекции вместе со связанными уроками
- список уроков группы
- создание, просмотр, редактирование и удаление уроков
- привязка урока к подсекции материалов
- вложения файлов к уроку

### 7. Задания и сдачи

- список заданий группы
- создание, просмотр и редактирование задания
- дедлайн и максимальный балл
- привязка задания к урокам, секциям и подсекциям материалов
- прикрепление файлов к заданию
- список сдач по заданию
- создание и редактирование сдачи
- несколько попыток сдачи
- проверка сдачи с выставлением балла и комментария

### 8. Расписание

- агрегированное расписание группы
- отдельный список событий расписания
- создание, просмотр, редактирование и удаление событий
- два типа событий:
  - `SPECIAL` - разовое событие
  - `WEEKLY` - повторяющееся недельное событие

### 9. Чаты

- список доступных чатов пользователя
- создание и открытие личного чата
- список групповых чатов внутри группы
- создание, редактирование и удаление группового чата
- просмотр сообщений
- отправка, редактирование и удаление сообщения
- ответы на сообщения
- вложения файлов к сообщениям
- realtime-обновления через `WebSocket`

## Технические ограничения и принципы

- backend реализован как модульный монолит на `NestJS`
- основной API - `REST` с префиксом `/api/v1`
- документация API публикуется через `Swagger` и хранится в `docs/openapi.yml`
- данные хранятся в `PostgreSQL`, доступ к данным идет через `Prisma`
- `Redis` подключен как инфраструктурный компонент
- файлы хранятся во внешнем `MinIO`, в БД лежат только метаданные
- frontend реализован как `SPA` на `Vue 3`, `Pinia`, `Vue Router`, `Vite`
- авторизация строится на короткоживущем `access token` и `refresh token`, который привязан к серверной сессии

## Что не входит в текущую реализацию

Ниже перечислено то, чего нет в коде и что не должно описываться как существующий функционал:

- отдельные сущности `класс` и `курс`
- глобальные роли сервиса `ADMIN` или `MODERATOR`
- `OAuth`-авторизация
- отдельная административная панель уровня всей платформы
